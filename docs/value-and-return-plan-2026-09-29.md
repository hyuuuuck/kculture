# K-Spot Now: visitor value and return loop (2026-09-29)

## Decision

K-Spot Now should be a **culture-visit decision desk**, not a broad events directory. An English-speaking independent visitor should be able to choose a meaningful cultural experience, understand the participation limits, save a tentative day, and return to see whether our published facts changed before travelling. Official listings supply evidence; our contribution is a reasoned comparison, a workable choice and a candid account of what remains unverified. Neither more pages nor a technical preflight is evidence that AdSense's low-value-content concern has been resolved.

## Release sequence and proof

1. **Restore dependable evidence, without false freshness.** Fix the changed Jinju source assertions and use an accessible official fallback, while retaining the desktop-site certificate failure as an unresolved limit. The published-event check must pass against live current records. If a source later fails, the failure must remain visible; no checker may silently renew an editorial date. A separate weather-refresh failure must not be mistaken for an event cancellation or a verified forecast.
2. **Remove expired advice from current reading.** Event hero dates, first answers, participation facts and saved-plan summaries must emphasize future usable conditions. A passed exception may remain in provenance/history, never as the lead decision. Assert specific facts only from a dated primary source; keep ticket inventory, accessibility and actual transport unconfirmed until tested.
3. **Make a return visit useful.** A saved plan should preserve a local baseline for material published facts—dates, venue, participation, price, schedule guidance and source link. On return, show exact changed fields and the current article/official notice; distinguish “no published change,” “older save with no baseline,” “source check due,” and “article withdrawn.” This is a check of *our publication*, not a claim to monitor live tickets or notify across devices. Do not add a thin indexable updates page.
4. **Operate an accountable editorial cadence.** Before each active-event weekend and within the site's 2–3-day source-monitoring window, inspect changed operator notices and publish only reviewed corrections. Record the material before/after and sources. Review the evergreen Seoul guide against currently open museum rooms and heritage services at least monthly or when a linked notice changes. A bot may flag drift; it must not authoritatively publish a changed admission, schedule or English-service claim.
5. **Prove reader value outside automated tests.** Ask at least three actual English-speaking independent visitors to choose one experience, identify the Korean destination and entry/language limit, then revise a saved plan after a simulated publication change. Record task completion, wrong assumptions and confusing copy. Obtain a separate accountable English/cultural/source review. This is an internal quality test, not a Google-mandated participant count. No fabricated participants or endorsement.
6. **Reassess, do not date-trigger resubmission.** Only after public freshness, content integrity, image/link/schema checks, the reader/editor results and production verification pass should the site-level content question be reassessed. 2026-10-04 is merely the next possible AdSense request date. Production deployment and another review request require explicit user authorization.
