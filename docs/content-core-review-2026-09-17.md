# 이미지 복구와 콘텐츠 핵심 보강 — 2026-09-17

## 이번 작업의 결론

로컬에서 깨진 이미지 표시를 복구했고, 현재 공개 대상으로 선정된 행사 6개와 가이드 4개의 본문을 수정했다. 단순히 글 길이를 늘리지 않고, 잘못 일반화된 입장 조건·개막일 예외·출처의 연도 차이를 고치고 문화적 맥락과 선택 근거를 보강했다. 독립된 사람의 편집 검토, 실제 독자 검증 또는 Google의 품질 판단을 수행한 것으로 기록하지 않는다.

이번 수정은 아직 운영 사이트에 배포하지 않았다. 광고·CMP·계정 설정, 재심사 신청, 커밋·푸시는 변경하지 않았다. 기존 작업 중인 변경을 보존했다.

## 이미지: 확인된 사실과 원인 범위

- 점검 시작 당시 `127.0.0.1:8766` 미리보기 서버가 응답하지 않았다. 해당 사진 파일은 소스와 빌드 결과에 존재했고 실제 이미지 형식이었다.
- 따라서 서버가 내려간 상태에서 캐시된 문서의 지연 로딩 사진이 실패했을 가능성이 높다. 다만 사용자가 스크린샷을 찍은 순간의 네트워크 로그는 없으므로 모든 과거 실패의 단일 원인이라고 확정하지 않는다.
- `npm run preview`가 빌드 후 독립된 로컬 서버를 시작하도록 변경했다. 이미 실행 중인 K-Spot 서버는 재사용하고, 같은 포트의 다른 서비스는 덮어쓰지 않는다. 명령 종료 후에도 유지되지만 컴퓨터 재부팅 후 자동 시작하는 서비스는 아니다.
- 이미지 전송 중 빌드 파일이 교체돼도 서버 전체가 종료되지 않도록 처리했다. 캐시 방지, 폰트 MIME, 확장자 없는 URL 처리도 보완했다.
- 검증을 소스 파일 존재 여부에서 **빌드 파일 → HTTP 상태·MIME·바이트 → 브라우저 이미지 디코딩**으로 확대했다. Impeccable의 실제 화면 점검 절차를 적용했다.
- 브라우저 홈의 이미지 9개 인스턴스가 모두 로드됐다. 빌드된 24개 HTML에서 참조하는 고유 이미지 7개는 HTTP 검사에 통과했다. Safari 데스크톱에서도 제보된 덕수궁·정원박람회·OCEAN 사진을 직접 확인했다.

## 다음 실제 조치

1. 질문지를 사용해 사람이 영어·문화적 해석·주장/출처 일치를 확인하고, 대상 독자의 혼동을 기록한다. 이는 내부 편집 절차이며 Google이 정한 참가자 수나 공식 승인 요건이 아니다.
2. 발견된 중대한 오해를 고친 뒤 해당 수정본으로 증빙을 묶는다. `data/editorial-release.json`의 지문이 변경되면 이전 검토를 자동 재사용하지 않는다.
3. 사용자의 명시적 배포 요청 후 운영에서 이미지·본문·시간 민감 사실·소유권 수단·개인정보 처리를 다시 확인한다. 그 후 별도로 재심사 여부를 판단한다.

권장하지 않는 조치: 글 수만 늘리기, 현재 사실 확인을 현장 체험으로 포장하기, 검사 통과를 승인 보장으로 표현하기, 과거 Search Console 색인 수만 기다리면서 콘텐츠 판단을 대체하기.
